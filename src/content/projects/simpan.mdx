I helped review and standardize the existing code while owning the ordering and payment flow across screens, state management, API integration, and tests. Refactoring and feature delivery happened alongside each other, with working features to protect throughout.

## Reviewing before refactoring

Before changing the inherited app, I reviewed the codebase to identify where refactoring would help and which areas could stay as they were. Preserving working features was part of that decision.

I helped standardize the Flutter code and migrate state management toward BLoC. This work happened alongside feature development, so improving the existing codebase remained part of our delivery work.

## Owning the ordering and payment flow

I owned the Flutter ordering and payment flow across screens, state management, API integration, and tests.

Testing followed the team's ownership model: each developer chose coverage, wrote tests, and reviewed them for their assigned screens and flows. For my work, I combined manual walkthroughs with Flutter unit and integration tests. These checks accompanied both refactoring and feature development, helping us verify that changes preserved the expected behavior.

## Delivery and reach

The team completed and handed over Simpan's iOS and Android app in October 2022, as documented in the [team case study](https://zero-one-group.com/case-studies/simplifying-investment-for-retail-investors-with-mobile-app). The product also reached [**1,000+ downloads**](https://play.google.com/store/apps/details?id=com.simpan.mobile.stg).

My contribution combined standardizing the inherited Flutter codebase with delivering the ordering and payment flow across screens, state management, API integration, and testing.

## What I took from the project

Simpan taught me to judge refactoring by how it supported delivery. A worthwhile change helped me finish the current feature, reduced the risk of bugs, and made future changes easier. That gave the cleanup a practical purpose as we continued building the app.
